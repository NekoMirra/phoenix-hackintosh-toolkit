## 黑苹果键盘 Windows 化（macOS 26.7.2 / x86）
- 环境：Hackintosh，SIP 自定义（kext 签名关闭），键盘 KT68 RGB（USB 1452-591），无 Homebrew。
- 装了 Karabiner-Elements 16.3.0（官方 GitHub dmg，installer 静默安装成功），驱动扩展已 `activated enabled`。
- 配置文件：~/.config/karabiner/karabiner.json，profile 名「Windows 习惯」，45 条 manipulator，4 组规则：
  1. Ctrl+编辑键(C/V/X/Z/A/S/F/N/O/P/T/W/R/数字/+/-) → Command，终端与虚拟机(RDP/PD/VMware)除外
  2. Ctrl+方向键/Backspace/Delete/Home/End → 按词移动删除（Option 系列）
  3. Alt+Tab/Alt+F4/Alt+←→ → Cmd+Tab / Cmd+Q / Cmd+[ ]
  4. Win 单击 → Cmd+Space（Spotlight），长按 → Command；Win+E 打开主目录，Win+D → fn+f11 显示桌面
- 要点：macOS 26 Tahoe 已移除 Launchpad，替代为 Spotlight 的「应用」视图（Fn+Shift+A / Cmd+Space+Cmd+1）。
- 坑：Karabiner 键名是 hyphen/equal_sign/open_bracket/close_bracket/spacebar，不是 minus/equal/left_bracket/space；用 karabiner_cli --lint-complex-modifications 校验。
- 待办：用户需在「隐私与安全性 → 输入监控 / 辅助功能」为 Karabiner 授权；装完记得实测 Ctrl+C/V。
- 追加：Shift 单击 → ⌃Space（切换上一个输入源），长按仍作 Shift（to_if_alone_timeout 350ms），左右 Shift 都启用；放在规则组第一位。系统未提供输入法内建 Shift 切换，故走 Karabiner。

## 黑苹果高能耗/风扇常转调查（同日 23:20）
- 硬件：Ryzen 7 8845H（8C16T，family 0x19）+ RTX 4060 Laptop（nullmoth nvfb/nvaccel 补丁驱动），外接 2560×1600@240Hz（HiDPI 逻辑 1280×800）。
- 根因三条：
  1) **完全没有 CPU 电源管理**：`machdep.xcpm.mode=0`、`hw.cpufrequency` 固定 3.8G，powermetrics 显示 3.89–4.12GHz、Package/Per-core C-state 驻留 0.00%，空闲负载仅 15% 却满频跑 → 主要热源。
  2) WindowServer 长期 90%+：sample 显示 72% 时间在 update_display_callback → CGXUpdateDisplay → Metal 合成，CA::OGL::render_layers 递归 300+ 层。台前调度 GloballyEnabled=1 是放大器。
  3) GPU 空载 19–20% 利用率、62–63℃，2560×1600@240Hz 每帧全屏合成。
- 已做（不需重启）：关台前调度（96.6%→85.1%）、reduceTransparency+reduceMotion（→81.6%），最终 69.5%。
- 已做（需重启生效）：EFI/OC 加入 AMDRyzenCPUPowerManagement.kext 0.7.2 + SMCAMDProcessor.kext 1.0.1（trulyspinach release 0.7.2f1，GitHub 直连被墙，用 ghfast.top 镜像下载），插入 Kernel→Add 第 3/4 位（Lilu→VirtualSMC 之后）。config 备份为 config.plist.bak-amdpm；整份 EFI 备份在 ~/Desktop/EFI-backup-20261103-232458。
- 关键坑：macOS 26 的 kmutil 无法运行时加载 OC 注入的 Lilu 插件（Failed to bind as.vit9696.Lilu），必须走 EFI 注入；kextutil 已是 kmutil 的壳。
- 验证脚本：~/verify-amd-pm.sh。回滚：Windows 下挂 ESP（104MB FAT32）改 config.plist 两项 Enabled=false，或用 bak 覆盖。
- 未解决/可选：240Hz + HiDPI 2x 合成是剩余最大功耗项，降 120Hz 或改 1x 可再降；风扇无 SMC 传感器键（无 SMCProcessor），无法读取/控制转速。

## 重启后验证（23:45）
- EFI 注入生效：`wtf.spinach.AMDRyzenCPUPowerManagement 0.7.2` + `SMCAMDProcessor 1` 均加载、active，SMCAMDProcessor 挂在 PM 节点下。
- 频率变化：**boost 被压回标称**——powermetrics 现在 3.22–3.81 GHz（`CPU Average ... 84.7%–100.2%`），重启前是 3.89–4.12 GHz / 109%。C-state 仍报 0.00%（AMD 上大概率读不到，非真实值）。
- `machdep.xcpm.mode` 仍是 0、`hw.cpufrequency` 仍是 3.8G —— 这两个在 AMD 上恒为该值，**不能作判断依据**；要看 powermetrics。
- 装了 AMD Power Gadget 0.7.2（ghfast.top 镜像下载 5.4MB，可行），但它**自己吃 43% CPU**，监控时数据被污染，用完必须 pkill；`defaults write ... startAtLogin -int 0` 不一定挡住（SMAppService）。
- 空闲 60 秒实测：WindowServer 99.8% + WorkBuddy GPU Helper 81% + Renderer 67%（≈2.5 核常驻）。GPU Core 利用率仅 12%、温度 61°C → **瓶颈是每帧合成的 CPU 开销，不是 GPU 算力**。
- 显示：内屏 2560x1600@240Hz，当前是 HiDPI「1280x800」，framebuffer 已是原生 2560x1600（无额外放大代价），所以调分辨率只能靠 1x 模式换像素，UI 会变小。
- 结论：剩余功耗只能靠降刷新率解决（用户明确不动），软件层已到底。`dispmode` 工具在 ~/WorkBuddy/.../tools/dispmode 可切模式。
- 坑：Bash 沙箱里 `ps`/`top`/`log`/`screencapture` 全被挡，需 `osascript ... with administrator privileges`；但每次授权会拉起 SecurityAgent+authorizationhost 并让 opendirectoryd 飙到 50%，干扰测量——应合并成一次长脚本。

## 驱动层深挖结论（23:58）
- 读了 SMCAMDProcessor-master 源码（约 2100 行）。机制：`pmKextRegister` 替换内核 PM 调度表，自实现两档调频；`pmRyzen_init_PState()` 把 **P1 改成 P0 的 80%**；`PSTATE_LIMIT=1`；步进阈值 STEPDOWN 0.12 / STEPUP 0.38（EFF_INTERVAL 0.15）。
- 用户态接口：selector 11 读 CPB、12 设 CPB（HWCR bit25）、13/14 切 P0↔P1、18/19 切 P1↔P2、15 裸写 PStateDef（危险）。
- 写了自己的工具 `tools/amdpm.c`（clang + IOKit，不用 root 即可调用）：status / cpb on|off / limit 0|1|2。
- **实测推翻假设**：limit P2、关 CPB 对频率零影响；基线有核跑到 2727MHz < P1 理论值 3040 → **Zen4 移动端走 CPPC 自主调频，PStateDef/PStateCtl 这类 MSR 在 Phoenix 上不生效**。所以"改 kext 支持 8845H"从机制上就无效，不是参数问题。
- 干净待机 50 秒实测（无人操作）：**WorkBuddy Helper(Renderer) 174.9%** + WindowServer 97.2% + WorkBuddy Helper(GPU) 81% + Electron 65.5% ≈ 4.2 核满载。→ 热的主因是本对话应用自身的持续重绘（长会话累积的卡片/动画），不是系统/驱动/屏幕。
- 温度偏移表只有 Zen1(0x17)，Phoenix 走默认 0 —— 恰好正确（Zen4 Tctl=Tdie）。
- 待验证：重启 WorkBuddy / 开新会话后 Renderer 占用是否掉下来。
